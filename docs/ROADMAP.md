# TechHunter Bot ROADMAP

Краткосрочный план. Горизонт: ближайшие 3 вехи (M1-M3). Далеко не загадываем,
дальнее держим в "Backlog" без детализации.

## Принципы

- Кнопки важнее команд. Команды остаются как быстрый доступ для опытных.
- Ноль технического спама в чат. Технические события (ошибки, капча,
  прогресс обучения) идут в логи или в один компактный статус-экран,
  а не отдельными сообщениями.
- Меню живёт в одном сообщении (edit-in-place), у каждого экрана есть
  "Назад". Карточки сделок - отдельные пуш-сообщения со своим рядом кнопок.
- Один визуальный язык во всём боте. Эмодзи допустимы только в UI бота как
  часть продукта; в коде, логах и доках - нет.
- Цены и оценки только из реальных данных. Ничего не выдумываем.
- Каждая веха заканчивается прогоном `tests.run_all` (зелёное) плюс ручной
  чек-лист.

## Состояние сейчас (база, от чего идём)

- Видимый Playwright-скрапер, сессионный шлюз капчи (одно уведомление).
- AI: specs/состояние/CLIP, dhash-дедуп фото.
- Оценка: самообучаемые медианы по состояниям, онбординг + периодический
  тихий переобход, persisted-флаг онбординга.
- Telegram: aiogram, команды /start /help /add /list /del /pause /resume
  /settings, карточки сделок, скрипт торга, уведомления онбординга.
- Слабые места: UI MVP-уровня, нет главного меню и сквозной навигации
  "Назад", технические сообщения, неоднородные карточки; известные риски
  надёжности (дедуп до обработки, глобальный дедуп против мультиюзера).

## M1 - Переработка интерфейса (АКТИВНАЯ ВЕХА)

Цель: бот выглядит как готовый продукт, навигация только кнопками,
никакого технического шума, единый стиль.

Объём (в работе):
1. Информационная архитектура. Главное меню как хаб: Подписки,
   Добавить, Настройки, Статус/Аналитика, Помощь. Любой экран
   возвращается в родителя и в хаб.
2. Навигация. Меню в одном сообщении через edit_text. Везде кнопка
   "Назад". Глубокие списки - с пагинацией кнопками.
3. Кнопки вместо команд. Добавление подписки через пошаговый
   диалог/подсказку с примерами; команды сохраняются как ярлыки.
4. Редизайн карточки сделки. Чёткая иерархия: заголовок, бейдж
   вердикта, цена vs рынок, профит (и "после ремонта"), отчёт о
   состоянии, дефекты, фото, ряд действий. Единые иконки и формат чисел.
5. Снижение шума. Онбординг - старт и итог одним сообщением каждый
   (уже есть, выверить тексты). Капча - одно сообщение + отражение в
   статус-экране. Ошибки - только в лог, опционально админу.
6. Экран Статус/Аналитика: состояние мониторинга, покрытие обучения
   (по каким моделям есть база, размер выборки), последний цикл.

Не входит в M1: новые источники, новые фичи данных, монетизация,
изменение математики оценки.

Definition of Done:
- Любой сценарий проходим только кнопками, из любого экрана есть выход.
- В чат не падает ни одного "сырого" технического сообщения.
- Карточка читается за 2 секунды, единый стиль во всех экранах.
- Команды по-прежнему работают как ярлыки.
- `tests.run_all` зелёный + новые тесты на сборку меню/карточки/навигации.
- Ручной чек-лист пройден на живом боте (оператор).

## M2 - Надёжность и корректность

Цель: не терять выгодные лоты и быть готовым к нескольким пользователям.

- Дедуп фиксировать ПОСЛЕ успешной обработки, а не до (транзиентный
  сбой не должен навсегда съедать лот).
- Доставка с дедупом per (пользователь, лот); `Listing` оставить как
  кэш обогащения, не как глобальный фильтр доставки.
- Аккуратный UX ошибок и капчи (статус вместо сообщений).
- Метрики цикла: сколько собрано, обработано, отправлено, отброшено и
  почему.

Definition of Done: транзиентные ошибки не теряют лоты; два тестовых
пользователя получают свои сделки независимо; цикл наблюдаем.

## M3 - Качество и прозрачность оценки

Цель: доверие к цифрам.

- Показ уверенности оценки (размер выборки, свежесть).
- Калибровка робаст-фильтров и порогов профита/скама на реальных данных.
- Отдельный экран "Цены по состояниям" по подписке.
- Кнопки реакции на сделку (норм/мимо) для калибровки порогов.

Definition of Done: в карточке видно, насколько оценке можно доверять;
пороги подстроены под реальный поток; есть петля обратной связи.

## Backlog (не детализируем, чтобы не забыть)

- Доп. площадки (Юла и пр.) за абстракцией источника.
- Локальный OCR для % батареи со скринов настроек.
- Мультипользователь в полном объёме (тарифы, лимиты).
- Экспорт/отчёты по найденным сделкам.
